# 01 — 需求、范围与成功标准

## 用户与目标

使用者：需要查询公司制度或产品事实的内部员工。输入为中文问题与可选对话历史；资料为带文档 ID、版本日期的合成制度和 FAQ。目标是**可信、有据可查**的回答，而不是尽可能答完。

## 范围内

- 文档搜索 `search_documents(query, limit)`：返回候选文档元数据、摘要、候选段落 ID；这些都不可当原文引用。
- 文档读取 `read_document(doc_id, paragraph_id?)`：可按可选段落 ID 精确读取原文；省略则读取当前短文档的全部段落。
- 真实 DeepSeek 模型自主选择下一工具、补充检索、引用作答、澄清、停止。
- 任务状态：完成、需澄清、证据不足、工具错误、未完成。
- 原文证据校验、版本信息、冲突安全约束、执行上限与 Trace。
- 通过 CLI 运行，自动化测试可离线执行，真实模型测试需自行提供 API Key。

## 不做的事

实际企业系统对接、真实生产知识库、登录授权、网页前端、云服务部署、真实敏感数据、复杂向量检索、答案修改企业制度；不上传真实密钥。

## 可检验的验收标准

| ID | 业务场景 | 判断标准 |
| --- | --- | --- |
| A1 | 明确答案 | 返回完成状态，答案与已读原文一致，引用包含真实 doc_id / paragraph_id / version_date / quote |
| A2 | 文档冲突 | D01、D02 内容矛盾且适用顺序不明，列出双方并追问，不选 15 或 30 作为唯一答案 |
| A3 | 资料外问题 | 资料缺失时输出缺口，禁止凭常识编造 |
| A4 | 改写问题 | 同一制度不同表述仍能检索并作可靠回答 |
| A5 | 上下文追问 | 结合历史解决“那由谁审批”，从 D03:p2 获取证据 |
| A6 | 工具失败 | 故障可见，真实模型可自选恢复或明确失败；不得把失败记录为成功 |
| A7 | 动态决策 | 保存至少两种**真实 DeepSeek**工具行动路径与可观察证据，不以脚本动作替代 |
| A8 | 安全与上限 | 无效引用拒绝标已完成，超过模型轮数或工具数时明确 incomplete |
| A9 | 文档变化敏感性 | 修改 D03:p1 后答案随原文变化；修改 D02 使与 D01 相同后应解除旧冲突，不能继续依赖静态 fact_value |
| A10 | 引用支持性 | 真实引用不能支持与原文相反的审批要求、审批人或产品支持状态；通用语义检查仍是未来工作 |
| A11 | 交付 | README、src、tests、examples、data、五份 docs、依赖、.env.example、GitHub URL、SHA |

## 具体数据约束

- `data/documents.json` 中 D01=报销30自然日、D02=报销15自然日；日期较新不足以推断优先级。两份均未说明适用范围和优先级。
- D03 规定年假提前3工作日申请，直属主管审批。
- D04 提供密码重置渠道；另有工牌和产品事实，用于扩展和反例。
- 一律标注“合成数据”，不得宣称真实企业制度。

## 完成的定义

完整交付必须具备真实 DeepSeek API 运行记录；离线 Mock 只能验证流程和本地守卫。人工检查至少六类验收点，保存三组以上真实模型输入、输出及 Trace，覆盖正常、证据不足、工具失败，且展示两种不同的模型决策路径。
